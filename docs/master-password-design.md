# StoreApp 加密方案：主密码 + secret 字段 AES-256-GCM

> 状态：**方案评审中，未实现**（确认后才动代码）
> 范围决策（已确认）：仅加密 `secret`（密钥/密码）字段；名称/账号/备注/分组保持明文；本轮不做锁库。
> 版本目标：v2.0

---

## 1. 目标与非目标

**目标**

1. 数据库文件被拷走、上云、送修时，所有密钥/密码在没有主密码的前提下不可读；
2. 老版本（v1.0/v1.1）的数据库打开后**自动、无感**升级为加密格式，不丢数据；
3. 现有全部功能（分组、搜索、显示/隐藏、一键复制、.sab 备份导入导出）行为不变。

**非目标（本轮不做）**

- 名称/账号/备注/分组 的保密（用户已确认接受其明文）；
- 空闲自动锁定、手动锁库按钮（v2.x 再做）；
- 主密码修改/找回（修改功能依赖本方案，可作为后续项；找回按既定策略**不提供**）。

## 2. 总体设计

### 2.1 密钥体系

```
主密码(你输入) + salt(随机16B,存库)
        │
        ▼  PBKDF2-HMAC-SHA256，200,000 轮，输出 32 字节
   AES-256 密钥 K（仅存内存，永 not 落盘）
        │
        ├─► 解密/加密 records.secret（AES-256-GCM，每条独立随机 nonce）
        └─► 校验 blob（验证主密码是否正确）
```

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| KDF | PBKDF2-HMAC-SHA256 | 与现有 .sab 备份一致，复用已验证代码路径 |
| 轮数 | 200,000 | 单次约 0.05~0.2s：你输一次可接受，暴力猜被拖慢数万倍 |
| salt | 16 字节 `os.urandom` | 每库随机生成一次，存 meta 表 |
| 密钥长度 | 32 字节（AES-256） | |
| 加密 | AES-256-GCM | 密文自带防伪标签，任何一个字节被改，解密即报错 |

### 2.2 存储格式（字节级）

**新增 `meta` 表**（key-value，存放参数与校验数据）：

```sql
CREATE TABLE IF NOT EXISTS meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

| key | value |
| --- | --- |
| `kdf_algo` | `pbkdf2-hmac-sha256` |
| `kdf_iterations` | `200000` |
| `kdf_salt` | base64(salt 16B) |
| `secret_format` | `gcm1`（格式版本号，供未来升级用） |
| `verify_blob` | base64( nonce(12B) ‖ GCM(固定常量) )，见 2.3 |

**`records.secret` 字段格式**：

```
旧(v1.x 弱混淆)：  base64(XOR(明文))                      ← 无前缀
新(v2.0 加密)：    "gcm1:" + base64( nonce(12B) ‖ 密文‖标签(16B) )
空值：             ""
```

- `gcm1:` 前缀 = 格式自描述，读取时一眼区分新旧格式，未来算法升级可加 `gcm2:`；
- nonce 每次加密随机生成 12 字节，同一明文两次加密结果必不相同；
- **AAD（附加认证数据）**：绑定 `b"secret:v1" + 记录ID`。作用：防止有人把 A 记录的密文剪切到 B 记录（换了位置就解不开），即防"移花接木"。

### 2.3 主密码校验（怎样知道密码输对了）

不能"先打开数据库再发现密码错"——密文本身无法告诉你密码对不对。做法：

- **首次设置**时，用 K 加密一段固定常量 `"StoreApp.verify.v1"`，把结果存进 `meta.verify_blob`；
- **每次解锁**：输入主密码 → 派生 K → 尝试解密 verify_blob：
  - 成功 → 密码正确，进入主界面；
  - 失败（GCM 标签不匹配）→ 密码错误，留在解锁对话框，**不显示任何数据**。

安全性说明：verify_blob 只能用来"验证一次猜测"，攻击者拿到它并不能反推主密码，只能配合 PBKDF2 一个一个猜（每猜一次都被 20 万轮计算拖慢）。

## 3. 交互流程

### 3.1 首次启动（库中无 `kdf_salt`）

```
启动 → 弹出「设置主密码」对话框
        ├ 输入密码（要求 ≥ 8 位，带强度提示）
        ├ 再输一遍确认
        ├ 红字警告：遗忘主密码 = 密钥/密码永久无法恢复，且不提供找回
        └ 取消 → 直接退出程序
     → 生成 salt、派生 K、写入 meta
     → 若库中有 v1.x 弱混淆的 secret：逐条解码 → 用 K 重新加密（迁移）
     → 迁移前自动备份：storeapp.db → data/backup-before-encrypt/storeapp-YYYYMMDD-HHMMSS.db
     → 进入主界面
```

### 3.2 日常启动

```
启动 → 弹出「解锁」对话框（只有密码输入框）
        ├ 密码正确 → 进入主界面，之后一切操作与现在完全一样
        ├ 密码错误 → 提示"主密码错误"，可重试；程序不加载任何记录
        └ 取消 → 退出
```

- K 只保存在进程内存中，不写盘、不进日志、不进备份；
- 关闭程序即销毁，下次重新输密码。

### 3.3 数据读写路径（对 UI 透明）

| 操作 | 变化 |
| --- | --- |
| 打开记录（表格、显示密钥、复制） | 数据层读到密文 → 用 K 解密 → UI 拿到的仍是明文，**界面代码零改动** |
| 新增/编辑记录 | 数据层在写库前用 K 加密 secret，其余字段照旧明文 |
| 搜索 | 只搜 名称/账号/网址/备注/标签/分组（**本来就不搜 secret**），无需改动，密文也不泄露 |
| 导出 .sab 备份 | 已解锁状态导出，payload 中 secret 为明文再被备份密码加密，**逻辑不变** |
| 导入 .sab 备份 | 导入时把每条 secret 用 K 加密后落库 |
| 解密失败（密文被改/损坏） | 该条显示 `⚠️ 解密失败`，程序不崩溃，其余记录正常 |

## 4. 迁移与回滚

**升级迁移（v1.x → v2.0）**

1. 打开库 → 无 `kdf_salt` → 走 3.1 首次设置流程；
2. 迁移前先复制一份整个 db 文件（明文级别与迁移前相同，只是防手滑不防攻击者）；
3. 遍历 `records`：
   - secret 为空 → 跳过；
   - 无 `gcm1:` 前缀 → 视为旧弱混淆 → `obfuscate.decode` 还原 → AES-GCM 加密写回；
   - 已有 `gcm1:` 前缀 → 已是新格式，跳过（幂等，中断重来也安全）；
4. 全部完成后写 `secret_format=gcm1`。

**回滚到旧版本 exe（已知行为，可接受）**

- 表结构未变、旧代码不读 meta → 程序能启动；
- 新格式 secret 被旧代码当弱混淆解码 → 解出乱码 → **界面上密钥显示为乱码，但不会崩溃、不会丢数据**；
- 重新用 v2.0 打开即恢复正常；
- ⚠️ 结论：升级后不要用旧 exe 编辑数据（看没关系，改了会把乱码当密码存回去）。

## 6. 风险与边界（照实告知）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **忘记主密码 = secret 永久不可解** | 名称/账号/备注仍可读，但密钥/密码无法恢复，无任何后门 | ① 主密码记入可信密码管理器/离线纸质；② **定期导出 .sab 备份**（独立备份密码，等于第二把钥匙） |
| 主密码太弱 | 暴力破解被 PBKDF2 拖慢但并非不可能 | 强制最短 8 位 + 强度提示（可调严） |
| 运行期内存明文 | 程序运行时 K 与解密结果在内存，木马/屏幕偷看仍可窃取 | 所有密码管理器的共同前提；关机/关程序即消失（本轮不做自动锁，靠随手关） |
| 元数据明文 | 用了哪些服务、账号名可见 | 已确认接受；将来可在 meta 加开关把账号一并加密，无需返工 |
| OneDrive 同步 | 升级后同步上云的是"密文 secret + 明文元数据" | 相比现状已是质变；data/ 仍被 .gitignore 挡在 Git 之外 |

## 7. 测试计划

1. **密码校验**：正确密码解锁 / 错误密码拒绝且不加载数据 / 空密码拒绝；
2. **加密往返**：含中文、emoji、超长、空值的 secret 全部稳定还原；
3. **篡改**：密文改 1 字节 → 解密报"解密失败"而非乱码；把 A 记录密文粘到 B 记录 → 因 AAD 绑定 ID 解不开；
4. **迁移**：v1.0 建的老库升级后逐条 secret 可解、格式变为 `gcm1:`、迁移中断可幂等重跑、自动备份文件存在；
5. **备份链路**：老 .sab 可导入 v2.0；v2.0 导出再导入到新库可解；
6. **回归**：现有 8 组冒烟测试全部保持通过（测试注入固定主密码）；
7. **打包**：exe 双击 → 首次设置 → 重启解锁 → 功能全绿。
